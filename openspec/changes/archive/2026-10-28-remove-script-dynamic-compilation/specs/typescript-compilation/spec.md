# Spec Delta

## MODIFIED Requirements

### Requirement: Complete language analysis
Компилятор MUST поддерживать полный синтаксис и систему типов объявленной версии TypeScript, включая TSX при заданной JSX-конфигурации. Типовые результаты MUST соответствовать эталонному компилятору при одинаковых входах. Дополнительные ограничения профиля исполнения без компиляции строк MUST сообщаться отдельно и согласованно в `Check` и `Compile`, без изменения upstream-кодов диагностик TypeScript.

#### Scenario: Advanced type checking
- **WHEN** проект использует generics, conditional и mapped types, template literal types, overloads и control-flow narrowing
- **THEN** проверка принимает и отклоняет программы по правилам объявленной версии TypeScript

#### Scenario: TSX source
- **WHEN** приложение предоставляет TSX-исходник, корректные JSX-настройки и объявления JSX API
- **THEN** компилятор проверяет JSX-выражения и типы свойств по правилам поддерживаемой версии

#### Scenario: Unsupported built-in source constructor
- **WHEN** исходник непосредственно вызывает встроенный `Function` или его однозначно разрешённый встроенный аналог для создания функции из строки
- **THEN** `Check` и `Compile` возвращают согласованную error-диагностику пространства `goja`, а исполняемая программа отсутствует

#### Scenario: Shadowed function name
- **WHEN** исходник вызывает пользовательскую функцию с именем `Function`, не связанную со встроенным конструктором
- **THEN** ограничение встроенного конструктора не применяется по одному лишь написанию имени

### Requirement: Checked compilation entry points
Любой публичный Go API, принимающий исполняемый исходник или AST, MUST проходить обязательную проверку перед генерацией программы. Скрипту MUST NOT предоставляться встроенный аналог этих API. Повторное использование результата MUST зависеть от исходников, настроек, версии языка, профиля, окружения типов и разделения стартовых и дополнительных модулей.

#### Scenario: Run source with an error
- **WHEN** операция выполнения исходника получает программу с ошибкой типов
- **THEN** возвращает диагностики до начала выполнения пользовательского кода

#### Scenario: Changed API after previous check
- **WHEN** сигнатура Go API изменена после успешного `Check`
- **THEN** компиляция использует новое окружение и не принимает прежний результат проверки как актуальный

#### Scenario: Changed prepared module set
- **WHEN** при неизменных исходниках приложение меняет `ModuleRoots`
- **THEN** новая программа учитывает новый разрешённый набор, а прежний результат подготовки не используется как эквивалентный

## ADDED Requirements

### Requirement: Additional prepared module roots
`Project.ModuleRoots` SHALL задавать дополнительные виртуальные пути исполняемых модулей либо имена host-модулей. `Check` и `Compile` MUST проверить их графы в общем снимке. Это поле MUST NOT само добавлять модули в стартовые точки. Неразрешимый или declaration-only source root MUST давать error-диагностику; одни объявления host-модуля SHALL допускаться для последующей проверки реализации при запуске.

#### Scenario: Computed import candidates
- **WHEN** приложение явно задаёт `/main.ts` в `EntryPoints`, а `/plugins/fast.ts` и `/plugins/safe.ts` в `ModuleRoots`
- **THEN** обе реализации и их зависимости проверены и подготовлены, но запуск программы сам по себе не выполняет их инициализаторы

#### Scenario: Invalid candidate is not silently deferred
- **WHEN** дополнительный модуль или его зависимость содержит ошибку типов, даже если скрипт никогда не выбирает этот модуль
- **THEN** `Check` и `Compile` сообщают ошибку до выполнения программы

#### Scenario: Explicit entry also listed as a module root
- **WHEN** модуль одновременно выбран стартовой точкой и указан в `ModuleRoots`
- **THEN** он выполняется по правилам стартовых точек и не создаётся второй экземпляр

#### Scenario: Declaration-only host candidate
- **WHEN** `ModuleRoots` содержит имя объявленного host-модуля без зарегистрированной реализации
- **THEN** проверка может завершиться успешно, а программа сохраняет требование реализации для проверки перед запуском

### Requirement: Immutable prepared program
Результат `Compile` MUST содержать неизменяемые исполняемые модули, разрешения импортов и требования окружения одного снимка. Изменения входных map, resolver, конфигурации или регистраций после компиляции MUST NOT менять эту программу. Замена кода или расширение разрешённого набора MUST требовать новой компиляции со стороны Go-приложения.

#### Scenario: Resolver changes after compilation
- **WHEN** после успешного `Compile` resolver начинает возвращать другую версию модуля или новый модуль
- **THEN** уже созданная программа использует прежний подготовленный код, а новый модуль не становится доступен

#### Scenario: Separate runtime instances
- **WHEN** один подготовленный `Program` запускается в двух совместимых runtime
- **THEN** код и правила разрешения одинаковы, а изменяемое состояние и экземпляры модулей разделены
