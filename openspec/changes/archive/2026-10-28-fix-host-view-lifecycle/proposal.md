# Proposal

## Why

Долгоживущий runtime бессрочно удерживает возвращённые `*struct` через сильные ссылки в `hostViews` и `hostViewSources`, даже когда скрипт больше не использует результаты. Это сохраняет связанные Go-данные и приводит к росту памяти с количеством созданных объектов.

## What Changes

- Определить автоматический жизненный цикл pointer-to-struct views: живое представление удерживает исходный Go-объект, а внутренний индекс runtime не препятствует их сборке.
- Сохранять идентичность достижимого view для одного Go-указателя и совпадающего контракта в пределах runtime, включая передачу исходного указателя обратно в Go.
- Заменить сильные таблицы слабым индексом с автоматическим удалением мёртвых записей, безопасным при фоновой очистке и замене записи.
- Исключить захват временных карт конверсии долгоживущими getters, setters, методами и callbacks.
- Добавить GC-регрессии и документировать асинхронное освобождение. Публичный API освобождения или отзыва views не добавляется.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `typed-host-api`: автоматическое освобождение host views и их метаданных, идентичность живых представлений и ограничение времени жизни временного состояния конверсии.

## Impact

- `host_conversion.go`, поля runtime в `runtime.go`, внутреннее представление host view и новый закрытый индекс: хранение source, поиск идентичности, очистка и захваты замыканий.
- `host_struct_test.go`, `host_cycles_test.go`, `host_functions_test.go` и новые внутренние GC-тесты: сохранение существующей семантики и проверка освобождения.
- `docs/typescript-embedding.md`: гарантии идентичности, достижимости и времени очистки.
- Новые зависимости, изменения публичных Go API и изменения деклараций TypeScript не требуются. Явные пользовательские адаптеры по-прежнему управляют своим преобразованием и владением данными самостоятельно.
