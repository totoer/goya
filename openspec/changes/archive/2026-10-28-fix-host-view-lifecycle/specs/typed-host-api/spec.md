# Spec Delta

## ADDED Requirements

### Requirement: Reachability-based host view lifetime
Автоматически создаваемые представления указателей на Go-структуры MUST удерживать исходный объект, пока представление достижимо. Runtime MUST NOT препятствовать сборке недостижимых представлений и связанных Go-данных только ради учёта идентичности. Освобождение SHALL происходить средствами GC без обязательного API release и без гарантии срока.

#### Scenario: Discarded host results in a long-lived runtime
- **WHEN** скрипт многократно вызывает host-функцию, возвращающую новые указатели на структуры, и не сохраняет результаты, а приложение продолжает удерживать runtime
- **THEN** представления и исходные данные без других сильных ссылок доступны для сборки GC без уничтожения runtime или явного освобождения каждого результата

#### Scenario: Live view protects its source
- **WHEN** единственная сильная ссылка на исходный Go-объект проходит через сохранённое Go-приложением или скриптом представление
- **THEN** GC не освобождает исходный объект, а чтение полей, разрешённые записи и вызовы методов продолжают работать

#### Scenario: Unreachable cycles are collectable
- **WHEN** представление и связанные данные образуют цикл без внешних сильных ссылок
- **THEN** внутренний учёт host views не препятствует сборке этого цикла

#### Scenario: Host ownership remains effective
- **WHEN** представление больше не используется, но исходный объект всё ещё удерживается Go-приложением или зарегистрированной привязкой
- **THEN** сборка представления не освобождает исходный объект вопреки оставшимся сильным ссылкам

### Requirement: Identity of live host views
В пределах одного runtime повторное преобразование одного Go-указателя с совпадающим контрактом MUST возвращать то же достижимое представление. Передача представления в Go-параметр соответствующего указательного типа MUST возвращать исходный указатель. После сборки представления SHALL допускаться создание нового; разные runtime и разные контракты MUST оставаться изолированными.

#### Scenario: Identity across calls and collection
- **WHEN** скрипт сохраняет host view, затем выполняются другие вызовы и GC, после чего host-функция возвращает тот же указатель с тем же контрактом
- **THEN** возвращается тот же объект, в том числе при доступе к рекурсивному полю, указывающему на исходную структуру

#### Scenario: Round trip without exposed members
- **WHEN** view структуры без доступных полей и методов передаётся обратно в host-функцию с параметром соответствующего указательного типа
- **THEN** функция получает исходный указатель без создания копии

#### Scenario: Matching pointer with different contracts
- **WHEN** один Go-указатель предоставлен в одном runtime через разные контракты, например readonly и mutable
- **THEN** представления не объединяются и каждое сохраняет доступность полей и разрешения своего контракта

#### Scenario: Separate runtime instances
- **WHEN** один Go-указатель предоставлен двум runtime
- **THEN** каждый runtime использует собственное представление и отклоняет передачу чужого runtime-объекта на host-границе

#### Scenario: Original pointer survives host field reassignment
- **WHEN** скрипт сохраняет view указателя, прочитанного из поля другой Go-структуры, после чего приложение заменяет указатель в этом поле
- **THEN** сохранённый view продолжает представлять прежний объект и при обратной передаче возвращает прежний указатель

### Requirement: Automatic host view bookkeeping reclamation
Метаданные идентичности собранных host views MUST удаляться автоматически без новых вызовов скрипта, создания новых views или обязательного вызова обработки jobs. Фоновая очистка MUST NOT выполнять пользовательский код или удалять запись нового живого представления при запоздалой обработке старого. Срок очистки SHALL зависеть от GC и планирования фоновой работы.

#### Scenario: Cleanup while runtime is idle
- **WHEN** несохранённые host views собраны и приложение сохраняет простаивающий runtime без дальнейших запусков
- **THEN** связанные записи учёта удаляются автоматически по мере выполнения фоновой очистки

#### Scenario: Delayed cleanup after replacement
- **WHEN** старый view уже собран, для того же ключа создано новое живое представление, затем выполняется запоздалая очистка старого
- **THEN** новое представление сохраняет идентичность и продолжает возвращаться при повторных преобразованиях

### Requirement: Conversion state lifetime isolation
Созданные bridge представления, методы, getters, setters и callbacks MUST NOT продлевать жизнь посторонних аргументов и результатов завершённой конверсии только через её временное состояние. Данные, необходимые самому receiver или callable, SHALL сохраняться на время их использования.

#### Scenario: Retained view does not retain sibling results
- **WHEN** host-вызов возвращает view и независимую коллекцию, а скрипт сохраняет только view
- **THEN** временное состояние преобразования не препятствует сборке отброшенной коллекции и её элементов

#### Scenario: Retained callable does not retain unrelated arguments
- **WHEN** после конверсии аргументов сохраняется созданный bridge callback или возвращённая функция, не зависящие от остальных аргументов
- **THEN** временное состояние конверсии не препятствует сборке этих посторонних аргументов и их копий

#### Scenario: Extracted method retains its receiver
- **WHEN** скрипт сохраняет метод host view, затем отбрасывает сам view
- **THEN** метод остаётся вызываемым с исходным receiver, а его необходимые Go-данные доступны до прекращения использования метода
