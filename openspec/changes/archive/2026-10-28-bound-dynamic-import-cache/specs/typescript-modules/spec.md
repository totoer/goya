# Spec Delta

## ADDED Requirements

### Requirement: Canonical dynamic import path retention
При одинаковом контексте программы, импортирующем модуле и режиме импорта runtime MUST использовать общее вспомогательное разрешение для эквивалентных написаний виртуального пути. Нормализация MUST сохранять правила подготовленного каталога, точное значение bare aliases и package specifiers и изоляцию разрешённых импортов программ. Требование MUST действовать также для `import()`, преобразованного в CommonJS.

#### Scenario: Equivalent virtual path spellings
- **WHEN** программа многократно импортирует подготовленный модуль через `./plugin`, `././plugin` и другие эквивалентные написания того же виртуального пути
- **THEN** варианты не создают отдельные записи вспомогательного кэша для одного контекста и режима, а импорты используют один экземпляр модуля

#### Scenario: Package names retain their resolution semantics
- **WHEN** после успешного импорта package specifier программа использует похожий specifier с запрещёнными сегментами либо явно заблокированный алиас
- **THEN** такой импорт отклоняется по замороженным правилам и не получает доступ через ранее сохранённое разрешение

#### Scenario: Program and importer isolation
- **WHEN** разные программы или импортирующие модули используют одинаковый текст specifier с разными подготовленными разрешениями
- **THEN** каждый импорт использует собственные разрешения и не получает доступ к модулю из чужого контекста

### Requirement: Bounded dynamic resolution retention
Вспомогательный runtime-кэш разрешений динамических импортов MUST иметь конечные лимиты числа записей и суммарного размера сохраняемых строк. Лимиты MUST охватывать все программы и оба пути исполнения ESM/CommonJS в одном runtime. Превышение лимита MUST приводить к вытеснению либо отказу от сохранения записи без отказа в допустимом импорте.

#### Scenario: Many aliases for one prepared target
- **WHEN** программа импортирует один подготовленный модуль через множество различных допустимых wildcard-алиасов, превышающее лимит записей
- **THEN** вспомогательный кэш остаётся в пределах обоих лимитов, все импорты успешны и модуль инициализируется один раз

#### Scenario: Oversized cache entry
- **WHEN** допустимый specifier разрешается в подготовленный модуль, но соответствующая запись превышает весь бюджет сохраняемых строк
- **THEN** импорт выполняется без сохранения этой записи, а последующие импорты остаются допустимыми

#### Scenario: Shared budget across execution paths and programs
- **WHEN** один runtime выполняет несколько совместимых программ с ESM-импортами и импортами, преобразованными в CommonJS
- **THEN** суммарное удержание вспомогательных разрешений остаётся в пределах общих runtime-лимитов

### Requirement: Dynamic resolution eviction preserves module state
Вытеснение вспомогательного разрешения MUST NOT удалять канонический экземпляр модуля или сбрасывать его инициализацию, live bindings, ожидающую асинхронную оценку либо сохранённую ошибку. Последующий импорт MUST использовать подготовленные правила без resolver и компиляции и сохранять проверки attributes, deferred evaluation и порядок promise jobs.

#### Scenario: Import evaluated module after eviction
- **WHEN** после успешного импорта и изменения экспортированного состояния вспомогательное разрешение вытеснено и модуль импортирован вновь
- **THEN** возвращается тот же namespace с изменённым состоянием без повторного выполнения инициализаторов

#### Scenario: Import pending or failed module after eviction
- **WHEN** разрешение вытеснено во время асинхронной инициализации либо после ошибки выполнения модуля
- **THEN** повторный импорт разделяет существующую инициализацию либо получает сохранённую ошибку без повторного выполнения модуля

#### Scenario: Import protocols after eviction or skipped retention
- **WHEN** разрешение отсутствует вследствие вытеснения или пропуска слишком большой записи, а импорт использует JSON attributes, deferred evaluation либо CommonJS interoperability
- **THEN** действуют те же проверки и протоколы выполнения, что и при первом импорте, без вызова resolver, чтения нового исходника или компиляции
