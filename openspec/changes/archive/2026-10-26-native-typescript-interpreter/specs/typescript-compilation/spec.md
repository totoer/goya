# Spec Delta

## Purpose

Определяет проверку и компиляцию TypeScript до исполнения, доступную Go-приложению независимо от создания runtime и согласованную с поддерживаемым стабильным релизом языка.

## ADDED Requirements

### Requirement: Stable TypeScript compatibility
Каждый релиз интерпретатора MUST объявлять точную поддерживаемую стабильную версию TypeScript. При выпуске новой версии интерпретатора SHALL выбираться последняя стабильная версия языка; компилятор и стандартные объявления MUST соответствовать ей. Бета-версии и nightly MUST NOT выбираться автоматически.

#### Scenario: Reproducible language version
- **WHEN** приложение запрашивает сведения о версии компилятора или повторяет компиляцию в том же релизе интерпретатора
- **THEN** получает одну точную версию TypeScript и одинаковые правила языка без загрузки обновлений из сети

#### Scenario: Stable language update
- **WHEN** интерпретатор обновляет поддерживаемый стабильный TypeScript
- **THEN** вместе обновляются объявления стандартной библиотеки и проверки совместимости, а версия доступна приложению

### Requirement: Complete language analysis
Компилятор MUST поддерживать полный синтаксис и систему типов объявленной версии TypeScript, включая TSX при заданной JSX-конфигурации. Результаты проверки MUST соответствовать эталонному компилятору при одинаковых исходниках, объявлениях, разрешении модулей и настройках.

#### Scenario: Advanced type checking
- **WHEN** проект использует generics, conditional и mapped types, template literal types, overloads и control-flow narrowing
- **THEN** проверка принимает и отклоняет программы по правилам объявленной версии TypeScript

#### Scenario: TSX source
- **WHEN** приложение предоставляет TSX-исходник, корректные JSX-настройки и объявления JSX API
- **THEN** компилятор проверяет JSX-выражения и типы свойств по правилам поддерживаемой версии

### Requirement: Independent type checking
Система SHALL предоставлять публичную операцию `Check`, принимающую исходники проекта, настройки и окружение типов. Она MUST возвращать диагностики без выполнения пользовательского кода и Go API и без создания исполняемой программы.

#### Scenario: Check without runtime
- **WHEN** Go-приложение проверяет проект без создания runtime
- **THEN** получает результат проверки типов и не наблюдает вызовов зарегистрированных функций или побочных эффектов TS-модулей

### Requirement: Mandatory compilation gate
`Compile` MUST выполнять ту же проверку, что и `Check`, для одного снимка проекта. Любая диагностика уровня error MUST блокировать создание исполняемой программы, включая ошибки конфигурации, синтаксиса, типов и разрешения модулей. Отключение проверки через настройки MUST быть отклонено.

#### Scenario: Incompatible assignment
- **WHEN** компилируется `const count: number = "hello";`
- **THEN** возвращается ошибка типов с указанием исходника, а исполняемая программа отсутствует

#### Scenario: Error in dependency
- **WHEN** точка входа корректна, но статически импортированный TS-модуль содержит ошибку типов
- **THEN** компиляция всего проекта завершается ошибкой до выполнения любого его модуля

#### Scenario: Attempt to skip checking
- **WHEN** приложение передаёт настройки, отключающие проверку проекта или его объявлений
- **THEN** компилятор отклоняет такую конфигурацию и не создаёт исполняемый результат

### Requirement: Strict checking defaults
По умолчанию система SHALL использовать семейство проверок `strict` поддерживаемой версии TypeScript. Явные настройки MUST обрабатываться одинаково в `Check` и `Compile`; они MUST NOT отключать обязательный этап проверки.

#### Scenario: Missing parameter type
- **WHEN** без изменения настроек проверяется функция `function double(x) { return x * 2; }`
- **THEN** выдаётся ошибка implicit any в соответствии с эталонным strict-режимом

#### Scenario: Explicitly permitted dynamic type
- **WHEN** программа использует допустимый явный `any` или type assertion
- **THEN** checker применяет правила TypeScript, не обещая обнаружить ошибки, которые эти правила допускают

### Requirement: Structured source diagnostics
Диагностики MUST содержать severity, код, сообщение, исходное имя файла и диапазон позиции, когда он существует, а также связанные позиции при наличии. Диагностики TypeScript SHALL сохранять upstream-коды; ошибки интеграции SHALL иметь отдельное пространство кодов.

#### Scenario: Host call type error
- **WHEN** функция объявлена как `add(a: number, b: number): number`, а исходник вызывает `add("1", 2)`
- **THEN** диагностика указывает на аргумент в исходном `.ts` файле и доступна Go-приложению без разбора форматированного текста

### Requirement: Checked compilation entry points
Любой публичный путь, принимающий исполняемый исходник или AST, MUST проходить обязательную проверку перед генерацией программы. Повторное использование результата проверки MUST зависеть от содержимого исходников, настроек, версии языка и окружения типов.

#### Scenario: Run source with an error
- **WHEN** операция выполнения исходника получает программу с ошибкой типов
- **THEN** возвращает диагностики до начала выполнения пользовательского кода

#### Scenario: Changed API after previous check
- **WHEN** сигнатура Go API изменена после успешного `Check`
- **THEN** компиляция использует новое окружение и не принимает прежний результат проверки как актуальный
