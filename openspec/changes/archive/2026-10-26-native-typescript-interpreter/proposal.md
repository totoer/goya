# Proposal

## Why

Проект должен стать встраиваемым интерпретатором актуального стабильного TypeScript на pure Go с обязательной проверкой типов до выполнения. Текущий Goja предоставляет JavaScript parser, компилятор и VM, но не понимает систему типов TypeScript и не может проверять зарегистрированный Go API при компиляции.

## What Changes

- **BREAKING**: перевести публичную компиляцию и выполнение на TypeScript; совместимость с прежними JavaScript API, AST, режимами и входными файлами не является требованием.
- Поддержать полный язык актуального стабильного TypeScript, включая TSX с предоставленной приложением JSX-инфраструктурой. Фиксировать точный релиз и соответствующие стандартные объявления в каждой версии интерпретатора; обновлять их вместе с проверками совместимости.
- Встроить официальный Go frontend TypeScript через сопровождаемую адаптацию исходников: parsing, binding, проверка типов, diagnostics и разрешение типов модулей.
- Предоставить отдельный `Check`; выполнять ту же обязательную проверку в `Compile` и во всех путях выполнения исходников. При ошибках не создавать исполняемый `Program`.
- Разработать преобразование проверенного TypeScript AST в исполняемое представление и байткод; адаптировать либо переписать необходимые части VM и стандартных объектов.
- Ввести единый типизированный реестр Go API: автоматическое описание обычных Go-сигнатур и структур, явное описание сложных случаев, согласованные объявления и runtime-привязки.
- Предоставлять внешние возможности только через регистрацию Go-приложением. Убрать автоматическое подключение `goja_nodejs`, CommonJS registry, `load` и `readFile` из CLI.
- Обеспечить компиляцию, проверку и выполнение внутри Go-процесса без cgo, Node.js, внешнего `tsc` и дочерних процессов.

## Capabilities

### New Capabilities

- `typescript-compilation`: версия языка, отдельная проверка типов, обязательная проверка при компиляции и структурированные диагностики.
- `typed-host-api`: единое описание типов и привязок Go API, правила преобразования и совместимость окружения с программой.
- `typescript-modules`: проверка и исполнение TS-модулей через resolver приложения, объявления типов и динамическая загрузка.
- `pure-go-execution`: исполнение TypeScript в Go VM, стандартная среда языка и отсутствие неявных внешних возможностей.

### Modified Capabilities

Отсутствуют: существующих спецификаций OpenSpec нет.

## Impact

Затрагиваются `token/`, `parser/`, `ast/`, `compiler*.go`, `vm.go`, `runtime.go`, `value.go`, `object*.go`, встроенные функции, Go reflection bridge, CLI `goja/`, зависимости, документация и тестовые наборы. Старые модули могут быть полностью переписаны. Потребуются upstream-исходники и стандартные объявления TypeScript с зафиксированным происхождением и лицензиями, а также сравнение диагностики с эталонным компилятором. Совместимость с Node.js, браузерным DOM и прежним JavaScript-интерфейсом не входит в цель.
