# Proposal

## Why

Проект уже проверяет, компилирует и выполняет TypeScript внутри Go-процесса, однако приложение не может предоставить редактору полноценные языковые возможности с тем же виртуальным проектом и типизированным Go API. Нужна встраиваемая языковая служба с прямым Go API и LSP, покрывающая все редакторские возможности `typescript-language-server` для поддерживаемого проектом TypeScript/TSX.

## What Changes

- Добавить изолированные сессии языковой службы: виртуальные исходники, несохранённые изменения, версии документов, настройки, отмена запросов и управляемое освобождение ресурсов.
- Предоставить одинаковые операции через типизированный публичный Go API и стандартный LSP поверх переданных приложением потоков ввода/вывода.
- Обеспечить диагностику, completion/resolve с auto-imports, hover, signature help, все виды навигации, references, rename, символы, highlights, folding, selection ranges, linked editing, call hierarchy, semantic tokens, inlay hints и code lens.
- Обеспечить форматирование, code actions/resolve, quick fixes, fix-all, рефакторинги, операции с импортами и обновление ссылок при переименовании файлов/каталогов, включая редакторские команды и расширения эталона.
- Использовать тот же закреплённый TypeScript frontend, стандартные объявления, настройки и `Environment`, что применяются при проверке и компиляции; обслуживать незавершённый код без ослабления обязательной проверки перед исполнением.
- Добавить необязательный `Project.ConfigFile`: имя виртуальной конфигурации из каталога проекта. `Check`/`Compile` и редактор используют согласованные `extends`, project references, настройки и исходные идентичности; при пустом поле сохраняется прежнее поведение.
- Проверять полноту по матрице редакторских возможностей `typescript-language-server` v6.0.2 с поведенческими fixtures через оба интерфейса. Различия, обусловленные закреплённой версией TypeScript, фиксировать явно; отсутствие функции не считать допустимым различием версий.
- Согласованные исключения паритета координат: EOF (включая EOF+1 в targets без statements) и исходники с U+2028/U+2029 используют стабильные UTF-16 координаты LSP исходного текста вместо истории внутреннего кэша и смешанных способов подсчёта строк TLS. Строки LSP разделяются CRLF/LF/CR; U+2028/U+2029 считаются обычными кодовыми единицами текста. Fixtures сохраняют сырые oracle-ответы; узкая проекция EOF и записанных oracle source spans явно обозначена и проверена хешем исходника, без произвольной замены результатов. EOF-проекция координат text edits и их command metadata требует отдельно записанного исходного span oracle и SHA-256; текст, порядок и семантика edits сохраняются.
- Сохранить работу при `CGO_ENABLED=0` без Node.js, дочерних процессов, сети и неявного доступа к файловой системе.

Граница паритета — редакторские возможности для TS/TSX, включая поддерживаемые `.mts`, `.cts` и declaration files. JavaScript/JSX как самостоятельный язык, выполнение JS-плагинов `tsserver`, произвольный passthrough `typescript.tsserverRequest`, npm/automatic typing acquisition и выбор внешнего `tsserver.js` не входят в change. Расширения/настройки VS Code и Neovim, отдельный CLI-сервер и готовые сетевые транспорты также не входят: приложение само выбирает способ подключения библиотеки.

## Capabilities

### New Capabilities

- `typescript-language-service`: встраиваемые сессии и полный набор редакторских операций над виртуальными TypeScript-проектами с согласованным окружением типов.
- `typescript-lsp`: публичный LSP-интерфейс к тем же операциям, жизненный цикл соединения, capabilities, синхронизация, клиентские взаимодействия и совместимость редакторских команд эталона.

### Modified Capabilities

- `typescript-compilation`: явная виртуальная конфигурация и граф project references в `Check`/`Compile`, без изменения вызовов с пустым `ConfigFile`.
- `typescript-modules`: согласованная идентичность исходных модулей при перенаправлении outputs referenced projects на TS-исходники без предварительной записи build artifacts.

## Impact

- Новые публичные пакеты `lsp` и `lsp/protocol`, внутренний слой сессий/адаптации и публичные примеры встраивания.
- Расширение воспроизводимого импорта `internal/tsfrontend/cmd/importupstream` пакетами language service, project system и LSP из того же commit, который закреплён в `internal/tsfrontend/manifest.json`; обновление file lock, лицензий и dependency inventory.
- Совместно используемые адаптеры виртуальных исходников, настроек и диагностик в `internal/tsfrontend`; текущие `Check`, `Compile` и runtime сохраняют контракт.
- Новые интеграционные проверки протокола, сессий, parity fixtures, race/isolation и автономной pure-Go сборки; документация возможностей и ограничений совместимости.

Согласованное расширение исключения EOF: при переносе в существующий файл без statements (пустой либо содержащий только whitespace/comments) TS 6 возвращает вставку в `EOF+1`. Встроенный API и LSP используют фактический EOF исходника. Fixtures сохраняют сырой ответ, независимо записанные TS6 span `start=SourceFile.end+1,length=0`, `SourceFile.end`, число statements и SHA-256. Проекция применяется только к точной вставке в выбранный target команды `Move to file`; текст, порядок edits и другие позиции сохраняются.
